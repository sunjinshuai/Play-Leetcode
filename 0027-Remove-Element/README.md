# 27. 移除元素

给定数组 `nums` 和整数 `val`，原地移除所有等于 `val` 的元素，返回剩余元素的个数 `k`。数组的前 `k` 个位置存放剩余元素，顺序可以改变，其余位置可以保留任意值。

[力扣题目](https://leetcode.cn/problems/remove-element/) · [本次提交](https://leetcode.cn/problems/remove-element/submissions/760286778/) · [已有 Java 源码](src/Main.java)

## 示例

| nums | val | 返回值 k | 有效前缀 |
| --- | --- | --- | --- |
| `[3, 2, 2, 3]` | `3` | `2` | `[2, 2]` |
| `[0, 1, 2, 2, 3, 0, 4, 2]` | `2` | `5` | `[0, 1, 3, 0, 4]` |
| `[]` | `3` | `0` | `[]` |
| `[3, 3]` | `3` | `0` | `[]` |
| `[1, 2]` | `3` | `2` | `[1, 2]` |

## 快慢双指针

用快指针 `i` 遍历数组，慢指针 `slow` 指向下一个写入位置，同时表示已经保留的元素数量。

- 遇到 `nums[i] == val`：跳过，`slow` 不变。
- 遇到 `nums[i] != val`：将元素写入 `nums[slow]`，再令 `slow++`。
- 遍历结束：返回 `slow`，数组前 `slow` 个元素就是结果。

## Java 实现

```java
class Solution {
    public int removeElement(int[] nums, int val) {
        int slow = 0;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != val) {
                nums[slow] = nums[i];
                slow++;
            }
        }
        return slow;
    }
}
```

已有 Java 源码中的 `j` 与这里的 `slow` 含义相同，算法一致。

## 执行过程

以 `nums = [3, 2, 2, 3]`、`val = 3` 为例：

| i | 当前元素 nums[i] | 操作 | 操作后的 slow | 有效前缀 |
| --- | --- | --- | --- | --- |
| 0 | 3 | 跳过 | 0 | `[]` |
| 1 | 2 | 写入 `nums[0]` | 1 | `[2]` |
| 2 | 2 | 写入 `nums[1]` | 2 | `[2, 2]` |
| 3 | 3 | 跳过 | 2 | `[2, 2]` |

最终数组为 `[2, 2, 2, 3]`，返回 `2`。只有前两项属于结果，后面的元素不需要清理。

## 为什么这样写？

### 为什么覆盖元素不会影响后续遍历？

每轮循环开始时都有 `slow <= i`：扫描过多少个元素，最多就保留多少个元素。因此写入位置只可能在当前位置或其左侧，不会覆盖尚未读取的元素。`slow == i` 时只是将元素赋值给自身。

### 为什么返回 slow？

每轮循环开始时，`nums[0 .. slow)` 恰好保存已遍历部分中所有不等于 `val` 的元素，并保持它们的相对顺序。这就是循环不变量，其中区间包含 `0`，不包含 `slow`。

初始时尚未遍历任何元素，`slow = 0`，有效前缀为空。每次遇到需要保留的元素，就把它追加到有效前缀末尾；遇到 `val` 则跳过。因此遍历结束时，`slow` 就是全部需要保留的元素数量。

### 为什么不用缩短数组或清空末尾？

Java 数组长度固定，题目中的“移除”是把保留元素放到前 `k` 个位置，并返回 `k`，不是改变 `nums.length`。末尾内容不参与结果判断，无需置零，也不需要额外创建数组。

题目允许改变元素顺序，而这份实现会保留原有的相对顺序，同样符合要求。

## 复杂度

- 时间复杂度：`O(n)`，其中 `n` 为数组长度，每个元素只扫描一次。
- 额外空间复杂度：`O(1)`，只使用固定数量的局部变量。
