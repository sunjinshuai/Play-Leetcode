# 70. 爬楼梯

需要爬 `n` 阶楼梯才能到达楼顶，每次可以爬 1 阶或 2 阶，求到达楼顶的不同方法数。步子的先后顺序不同，视为不同方法。

[力扣题目](https://leetcode.cn/problems/climbing-stairs/)

## 示例

| n | 返回值 | 方法 |
| --- | --- | --- |
| 1 | 1 | `1` |
| 2 | 2 | `1 + 1`、`2` |
| 3 | 3 | `1 + 1 + 1`、`1 + 2`、`2 + 1` |

输入约束：`1 <= n <= 45`。下面的实现按题目保证的合法输入编写。

## 思路：递归 + 记忆化搜索

定义 `f(n)` 为爬到第 `n` 阶的方法数。从最后一步倒着考虑，到达第 `n` 阶只有两种情况：

1. 最后爬 1 阶：之前已经到达第 `n - 1` 阶，有 `f(n - 1)` 种方法。
2. 最后爬 2 阶：之前已经到达第 `n - 2` 阶，有 `f(n - 2)` 种方法。

这两类方法的最后一步不同，不会重复；每种合法方法也必然属于其中一类，不会遗漏。因此可以直接相加：

```text
f(1) = 1
f(2) = 2
f(n) = f(n - 1) + f(n - 2)，其中 n >= 3
```

普通递归会反复计算相同的子问题。例如，`f(5)` 需要 `f(4)` 和 `f(3)`，而计算 `f(4)` 时又需要 `f(3)`。

用哈希表 `map` 保存已经算出的答案：计算前先查询，命中就直接返回；没有命中才递归计算并保存。这就是记忆化搜索，也是一种自顶向下的动态规划。

## Java 实现

保留递归和哈希表缓存的实现思路，使用泛型创建 `HashMap`，并将缓存查询结果保存到局部变量，避免命中时重复查询。

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    private final Map<Integer, Integer> map = new HashMap<>();

    public int climbStairs(int n) {
        if (n == 1) {
            return 1;
        }
        if (n == 2) {
            return 2;
        }

        Integer cached = map.get(n);
        if (cached != null) {
            return cached;
        }

        int res = climbStairs(n - 1) + climbStairs(n - 2);
        map.put(n, res);
        return res;
    }
}
```

## 逐段讲解

### 1. 用成员变量保存计算结果

```java
private final Map<Integer, Integer> map = new HashMap<>();
```

- `key` 是台阶数 `n`。
- `value` 是爬到第 `n` 阶的方法数。
- 例如 `map.put(3, 3)` 表示爬到第 3 阶有 3 种方法。

`map` 是实例成员，同一个 `Solution` 对象中的所有递归调用共享这一份缓存。如果在方法内部每次都创建新表，不同递归调用就无法共享已经算出的结果。

`final` 表示不能让 `map` 重新指向另一张表，不妨碍通过 `put` 添加缓存。`new HashMap<>()` 使用泛型类型推断，避免原始类型 `new HashMap()` 带来的未检查转换警告。

### 2. 设置递归终止条件

```java
if (n == 1) {
    return 1;
}
if (n == 2) {
    return 2;
}
```

1 阶只有一种爬法；2 阶可以连续爬两次 1 阶，也可以直接爬 2 阶。

这两个条件既给出了最小问题的答案，也保证递归能够终止。因为只有 `n >= 3` 才会继续递归，所以合法输入不会递归到 `n = 0` 或负数。

基础状态直接返回即可，不需要存入缓存，因为它们本身就只花费常数时间。

### 3. 先检查是否计算过

```java
Integer cached = map.get(n);
if (cached != null) {
    return cached;
}
```

`map.get(n)` 查找当前台阶数的答案。本实现只保存非空结果，因此返回 `null` 就代表尚未计算。

这里必须用 `Integer` 接收可能为空的查询结果。如果写成 `int cached = map.get(n)`，缓存未命中时会尝试将 `null` 自动拆箱为 `int`，从而抛出 `NullPointerException`。确认非空后，`return cached` 可以安全拆箱。

### 4. 递归计算并缓存

```java
int res = climbStairs(n - 1) + climbStairs(n - 2);
map.put(n, res);
return res;
```

两个递归调用分别求出最后爬 1 阶、最后爬 2 阶对应的方法数，相加得到当前答案。先将结果保存，再返回给上一层调用。

这里的 `res` 一定是已计算出的整数，可以直接使用 `int`；存入 `Map<Integer, Integer>` 时会自动装箱。

缓存命中后已经 `return`，所以后面的计算不需要再包在 `else` 中。

## 执行过程：n = 5

从空缓存开始，Java 会先求加号左侧的递归调用，再求右侧：

```text
climbStairs(5)
  → climbStairs(4)
      → climbStairs(3)
          → climbStairs(2) = 2（基础状态）
          → climbStairs(1) = 1（基础状态）
          → 保存 map[3] = 3，返回 3
      → climbStairs(2) = 2（基础状态）
      → 保存 map[4] = 5，返回 5
  → climbStairs(3) = 3（命中缓存，不再展开）
  → 保存 map[5] = 8，返回 8
```

| 完成的计算 | 计算方式 | 此时的缓存内容 |
| --- | --- | --- |
| `f(3)` | `2 + 1 = 3` | `{3=3}` |
| `f(4)` | `3 + 2 = 5` | `{3=3, 4=5}` |
| `f(5)` | `5 + 3 = 8` | `{3=3, 4=5, 5=8}` |

表格按台阶数展示缓存，`HashMap` 本身不保证遍历顺序。最终答案是 8；第二次调用 `climbStairs(3)` 时直接复用第一次的结果。

## 为什么缓存能减少计算？

不加缓存时，同一个台阶数会出现在递归树的不同分支中，每次都重新展开，调用数量随 `n` 指数增长。

加上缓存后，每个 `n >= 3` 的状态只会展开计算一次，之后再次访问时直接返回。递归始终向更小的台阶数推进，没有循环依赖，因此首次计算一个状态时，两个子状态都能先得到答案。

需要区分“调用一次”和“展开计算一次”：例如 `climbStairs(3)` 仍可能被调用多次，但只有首次未命中缓存时才继续递归。基础状态也可能被访问多次，但每次都立即返回。

## 边界与常见问题

- **`1 + 2` 和 `2 + 1` 为什么分别计数？** 两种方法的步子顺序不同，最后一步分别为 2 阶和 1 阶，属于递推式中的不同类别。
- **为什么不处理 `n = 0`？** 题目保证 `n >= 1`，当前终止条件也不会让合法输入递归到 0。如果扩展输入范围，需要先定义 0 阶的含义，不能直接沿用本实现。
- **会不会整数溢出？** 最大输入 `n = 45` 的答案是 `1836311903`，小于 Java `int` 的最大值 `2147483647`。若扩展到 `n = 46`，答案 `2971215073` 就会超出 `int` 范围。
- **同一对象重复调用需要清空缓存吗？** 不需要。这里答案只取决于台阶数 `n`，先前缓存的结果仍然有效；新建 `Solution` 对象则会创建独立的空缓存。
- **和斐波那契数有什么关系？** 递推关系相同，但初始值不同。若定义斐波那契数 `F(0) = 0、F(1) = 1`，则爬楼梯答案为 `f(n) = F(n + 1)`。

## 复杂度

以下分析以缓存初始为空、首次求解 `n` 阶为准，哈希表操作按平均常数时间计算。

| 方式 | 时间复杂度 | 额外空间复杂度 |
| --- | --- | --- |
| 普通递归 | 指数级，常用上界为 `O(2^n)` | `O(n)`，递归调用栈 |
| 记忆化递归 | `O(n)` | `O(n)`，哈希表与递归调用栈 |

记忆化递归最多保存 `n - 2` 个非基础状态，每个状态只展开一次，每次进行常数次缓存操作和递归调用，因此总时间为 `O(n)`。

递归会沿着 `n、n - 1、n - 2、…` 向下展开，最大栈深度为 `O(n)`。缓存和递归栈各占 `O(n)`，相加后仍为 `O(n)`，不能只统计缓存而忽略调用栈。
