# 169. 多数元素

给定非空整数数组 `nums`，返回出现次数严格超过数组长度一半的元素。题目保证这样的元素存在。

[力扣题目](https://leetcode.cn/problems/majority-element/) · [Java 源码](Java/Solution.java)

## 示例与约束

| nums | 返回值 |
| --- | --- |
| `[3,2,3]` | `3` |
| `[2,2,1,1,1,2,2]` | `2` |
| `[7]` | `7` |

- `1 <= nums.length <= 50000`。
- `-10^9 <= nums[i] <= 10^9`。
- 多数元素的次数必须大于 `n / 2`（整数除法），不是大于等于，也不只是所有数字中出现次数最多。
- 进阶要求时间复杂度 `O(n)`、额外空间复杂度 `O(1)`。

## 思路：Boyer–Moore 投票算法

每次消去两个不同的数字，多数元素最终一定会留下。

维护两个变量即可模拟抵消过程，无需真的删除数组元素：

- `candidate`：当前尚未被抵消的数字，也就是候选值。
- `count`：当前候选值尚未被抵消的数量，**不是它在原数组中出现的总次数**。

遍历每个 `num`：

1. 如果 `count == 0`，之前处理的数字已经全部配对抵消，让当前数字成为新候选。
2. 如果当前数字等于候选，`count` 加一。
3. 否则，当前数字与一个候选相互抵消，`count` 减一。

整个已处理前缀可以看成“若干对不同数字 + `count` 个相同的候选值”。前面的配对可以丢弃，只需要保存剩下的候选和数量。

## Java 实现

```java
class Solution {
    public int majorityElement(int[] nums) {
        int candidate = 0;
        int count = 0;
        for (int num : nums) {
            if (count == 0) {
                candidate = num;
            }
            count += num == candidate ? 1 : -1;
        }
        return candidate;
    }
}
```

`candidate` 初始为 `0` 只是占位。第一次循环时 `count == 0`，候选会被替换成第一个元素，因此零和负数都可以正常处理。

选定新候选后，仍然执行下面的计数语句；此时 `num == candidate`，所以当前元素贡献一票。不能在设置候选后直接跳过本轮，也不能把计数语句改成只在 `else` 中执行而漏记这一票。

三元表达式 `count += num == candidate ? 1 : -1` 可以展开为：

```java
if (num == candidate) {
    count++; // 相同数字，积累一个
} else {
    count--; // 不同数字，抵消一个
}
```

## 逐步执行

以 `[2,2,1,1,1,2,2]` 为例：

| 下标 | 当前数字 | 操作 | 更新后的 candidate | 更新后的 count |
| --- | --- | --- | --- | --- |
| 0 | 2 | 票数为零，选 2，并记一票 | 2 | 1 |
| 1 | 2 | 相同，加一票 | 2 | 2 |
| 2 | 1 | 不同，抵消一票 | 2 | 1 |
| 3 | 1 | 不同，抵消一票 | 2 | 0 |
| 4 | 1 | 票数为零，选 1，并记一票 | 1 | 1 |
| 5 | 2 | 不同，抵消一票 | 1 | 0 |
| 6 | 2 | 票数为零，选 2，并记一票 | 2 | 1 |

返回 `2`。它在数组里出现了四次，但最后 `count` 只有 `1`，因为其他三次已经参与了抵消。

当某轮结束后 `count == 0` 时，变量 `candidate` 中虽然还保留旧值，但此时没有有效候选。下一轮才使用新元素重新选候选。

## 为什么最后留下的一定是多数元素？

设多数元素为 `M`，出现 `m` 次，其他元素总共出现 `r` 次。题目保证 `m > r`。

消去两个不同的数字，只有两种情况：

- 一方是 `M`，另一方不是：两边各少一个，仍有 `m - 1 > r - 1`。
- 两方都不是 `M`：其他元素少两个，`M` 的优势更大。

因此，消去任意一对不同数字，都不会破坏 `M` 相对其他所有数字的数量优势。`M` 不可能被全部消掉，最终未配对的数字只能是 `M`。

这也解释了为什么可以中途更换候选：当 `count` 归零时，丢弃的是若干对不同数字，不会改变剩余部分的多数元素。

## 题目保证为什么重要？

如果数组不保证存在多数元素，投票算法只能选出候选，不能证明候选真的超过一半。例如 `[1,2,3]` 最后会选出 `3`，但它不是多数元素。

这种情况下需要再遍历一次，统计候选的实际次数，确认是否严格大于 `nums.length / 2`；不存在时如何返回，应由接口约定。本题保证多数元素存在，因此无需第二次验证，也不额外处理空数组或 `null`。

## 复杂度与其他思路

- 时间复杂度：`O(n)`，只遍历一次。
- 额外空间复杂度：`O(1)`，只保存候选与票数。
- 不修改输入数组。

哈希表统计次数也能求解，平均时间为 `O(n)`，额外空间为 `O(n)`。排序后取 `nums[n / 2]` 也成立，因为超过一半的相同元素必然覆盖中间位置，但通常需要 `O(n log n)` 时间，原地排序还会改变输入顺序。

## 能否直接使用 ^= 累积异或？

不能。`result ^= num` 等价于 `result = result ^ num`，它利用以下规则抵消相同数字：

```text
a ^ a = 0
0 ^ a = a
```

因此，出现偶数次的数字会全部抵消，出现奇数次的数字各留一份，再相互异或。这个结果反映的是出现次数的奇偶性，无法判断哪个数字超过数组长度的一半。

例如：

```text
nums = [2, 2, 3]

2 ^ 2 ^ 3
= 0 ^ 3
= 3
```

多数元素是 `2`，但它出现两次，被异或消掉了，结果反而是 `3`。

| 题目或方法 | 抵消规则 | 成立的前提 |
| --- | --- | --- |
| 136. 只出现一次的数字：异或 | 相同数字两两抵消 | 一个数字出现一次，其余数字都出现两次 |
| 169. 多数元素：投票法 | 不同数字两两抵消 | 一个数字的出现次数超过其他所有数字的总次数 |

两种方法虽然都有“抵消”的直觉，但抵消规则不同，不能直接套用。

## 位运算的可行方案：逐位统计

不能直接累积异或，并不代表不能使用位运算。本题可以统计每个二进制位上 `1` 的数量，再拼出多数元素。

设多数元素为 `M`。对任意一位：

- 如果 `M` 的这一位为 `1`，仅 `M` 就贡献了超过一半的 `1`。
- 如果 `M` 的这一位为 `0`，所有可能贡献 `1` 的其他元素加起来也不到一半。

所以，这一位上 `1` 的数量超过一半，当且仅当 `M` 的这一位为 `1`。

例如 `[2,2,3]`：

```text
2 = 10
2 = 10
3 = 11

最低位：1 出现 1 次，不超过一半 → 答案这一位为 0
下一位：1 出现 3 次，超过一半   → 答案这一位为 1

答案 = 10（二进制）= 2
```

### Java 实现

```java
class Solution {
    public int majorityElementByBits(int[] nums) {
        int result = 0;
        for (int bit = 0; bit < 32; bit++) {
            int ones = 0;
            for (int num : nums) {
                ones += (num >>> bit) & 1;
            }
            if (ones > nums.length / 2) {
                result |= 1 << bit;
            }
        }
        return result;
    }
}
```

源码用 `majorityElementByBits` 区分两种方法；单独提交到力扣时，将方法名改为 `majorityElement`。

| 表达式 | 含义 |
| --- | --- |
| `num >>> bit` | 无符号右移，把待检查的位移到最低位，高位补零 |
| `& 1` | 只取最低位，得到 `0` 或 `1` |
| `1 << bit` | 生成只有第 `bit` 位为 `1` 的整数，位编号从 0 开始 |
| `result |= 1 << bit` | 按位或，将结果的对应位设为 `1`，保留其他位 |

这里使用的是 `|=`（按位或赋值），不是 `^=`（按位异或赋值）。按位或用于设置某一位，异或则会翻转对应的位。

### 负数、复杂度与适用边界

Java 的 `int` 使用 32 位补码。代码统计全部 32 位，包括第 31 位的符号位，因此也能正确还原负数。`1 << 31` 的值为 `Integer.MIN_VALUE`，它恰好表示只有符号位为 `1` 的位模式，并不是本算法中的错误溢出。

- 时间复杂度：`O(32n)`，固定 32 位时记为 `O(n)`，但需要扫描数组 32 次。
- 额外空间复杂度：`O(1)`。
- 不修改输入数组。

这种方法同样依赖多数元素存在。例如 `[1,2,4]` 没有多数元素，每一位上的 `1` 都不超过一半，最终得到 `0`，甚至不在原数组中。

投票法和逐位统计都满足进阶要求；投票法只扫描一次，通常优先使用。直接将所有元素异或则无法解决本题。
