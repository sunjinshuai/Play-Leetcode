# 209. 长度最小的子数组

给定正整数数组 `nums` 和正整数 `target`，返回元素和大于等于 `target` 的连续子数组的最小长度。如果不存在，返回 `0`。

[力扣题目](https://leetcode.cn/problems/minimum-size-subarray-sum/) · [Java 源码](Java/Solution.java)

## 示例

| target | nums | 返回值 | 说明 |
| --- | --- | --- | --- |
| 7 | `[2,3,1,2,4,3]` | 2 | `[4,3]` 的和为 7 |
| 4 | `[1,4,4]` | 1 | 单个 4 即可满足条件 |
| 11 | `[1,1,1,1,1,1,1,1]` | 0 | 整个数组的和仍不足 11 |

子数组必须连续，不能跳过中间的元素；条件是和 **大于等于** `target`，不要求恰好相等。

## 思路：滑动窗口

用 `i` 和 `j` 表示窗口的左右边界，用 `sum` 维护窗口内元素之和。

1. 右边界向右移动，将新元素加入 `sum`。
2. 只要 `sum >= target`，当前窗口就是一个合法答案，先更新最小长度。
3. 移除最左侧元素并右移 `i`，继续尝试缩短窗口。
4. 当窗口和不足时，继续扩大右边界。

这个方法依赖 **所有元素都是正数**：扩大窗口会增加总和，缩小窗口会减少总和。固定右边界时，一旦窗口和不足，再收缩只会更小，因此可以停止收缩。

被移除的左端点也无需回头考虑：以它为起点的合法窗口已经被记录，之后右边界继续右移只会让窗口更长，不可能改善答案。

## Java 实现

```java
class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int i = 0;
        int sum = 0;
        int result = Integer.MAX_VALUE;

        for (int j = 0; j < nums.length; j++) {
            sum += nums[j];

            while (sum >= target) {
                result = Math.min(result, j - i + 1);
                sum -= nums[i];
                i++;
            }
        }

        return result == Integer.MAX_VALUE ? 0 : result;
    }
}
```

## 窗口变化

以 `target = 7, nums = [2,3,1,2,4,3]` 为例，下标从 0 开始：

| j（右边界） | 加入元素后的窗口和 | 收缩时检查的合法窗口 | 收缩结束后的窗口 | 当前最短长度 |
| --- | --- | --- | --- | --- |
| 0 | 2 | 无 | `[2]` | 尚未找到 |
| 1 | 5 | 无 | `[2,3]` | 尚未找到 |
| 2 | 6 | 无 | `[2,3,1]` | 尚未找到 |
| 3 | 8 | `[2,3,1,2]`，长度 4 | `[3,1,2]`，和 6 | 4 |
| 4 | 10 | `[3,1,2,4]`、`[1,2,4]`，长度 4、3 | `[2,4]`，和 6 | 3 |
| 5 | 9 | `[2,4,3]`、`[4,3]`，长度 3、2 | `[3]`，和 3 | 2 |

最终返回 `2`。

## 关键细节

- **为什么用 `while`，不能只用 `if`？** 同一个右边界下可能连续收缩多次。最后一轮要先检查 `[2,4,3]`，再检查 `[4,3]`，只收缩一次会漏掉更短的窗口。
- **为什么先更新答案，再收缩？** 收缩前的窗口已满足条件，移除元素后可能不再满足，必须先记录当前长度。
- **长度为什么是 `j - i + 1`？** 两端下标都包含在窗口内，单个元素时左右下标相同，长度为 1。
- **为什么初值是 `Integer.MAX_VALUE`？** 用一个大于所有合法长度的值表示尚未找到答案，方便通过 `Math.min` 更新；遍历后初值未变则返回 0。
- **为什么先执行 `sum -= nums[i]`，再执行 `i++`？** 必须先移除当前左端元素，再移动左边界；顺序颠倒会减掉错误的元素。这两行等价于 `sum -= nums[i++]`，拆开后更容易看清执行顺序。
- **有负数还适用吗？** 不能直接套用。负数会破坏窗口和的单调性，例如 `target = 3, nums = [1,-1,3]`，该实现会错过长度为 1 的 `[3]`。
- **`sum` 会溢出吗？** 本题最多有 `100000` 个元素，每个元素最多为 `10000`，总和最多为 `1000000000`，Java `int` 足够。若扩大输入范围，需要重新评估并考虑 `long`。
- **是否修改输入？** 不修改，只读取数组元素。

## 复杂度

- 时间复杂度：`O(n)`。虽然有嵌套循环，但左右指针都只向右移动，每个元素最多入窗和出窗各一次。
- 额外空间复杂度：`O(1)`，仅使用几个变量。

## 进阶：前缀和 + 二分查找

定义 `prefix[0] = 0`，`prefix[i + 1] = prefix[i] + nums[i]`。则子数组 `[left, end)` 的和为 `prefix[end] - prefix[left]`。

对于每个起点 `left`，在 `[left + 1, n]` 中二分查找第一个满足 `prefix[end] >= prefix[left] + target` 的位置，候选长度为 `end - left`。若找不到，则该起点没有合法子数组。

由于原数组全为正数，前缀和严格递增，能够进行二分查找。总时间复杂度为 `O(n log n)`，额外空间复杂度为 `O(n)`；本题优先使用更简单的滑动窗口。
