# 215. 数组中的第 K 个最大元素

给定整数数组 `nums` 和整数 `k`，返回按从大到小排列时位于第 `k` 位的元素。重复值分别占据名次，不能先去重。

[力扣题目](https://leetcode.cn/problems/kth-largest-element-in-an-array/) · [Java 源码](Java/Solution.java)

## 示例

| nums | k | 返回值 |
| --- | --- | --- |
| `[3,2,1,5,6,4]` | 2 | 5 |
| `[3,2,3,1,2,4,5,5,6]` | 4 | 4 |

第二个数组降序排列后为 `[6,5,5,4,3,3,2,2,1]`，两个 5 分别占第 2、3 位，所以第 4 大是 4。

输入约束：`1 <= k <= nums.length <= 100000`，`-10000 <= nums[i] <= 10000`。下面的实现按题目保证的合法输入编写。

## 思路：维护大小为 k 的最小堆

我们只需要保留最大的 `k` 个元素。这些元素中最小的那个，就是整个数组的第 `k` 大元素。

用最小堆维护这些候选元素，堆顶始终是堆内最小值：

1. 遍历数组，把当前元素加入最小堆。
2. 如果堆的大小超过 `k`，弹出堆顶，也就是当前候选元素中最小的数。
3. 遍历结束后，堆里留下最大的 `k` 个元素，返回堆顶。

每轮结束时，堆内保留已遍历元素中最大的 `min(k, 已遍历数量)` 个数。加入新元素后，如果有 `k + 1` 个候选，只需淘汰最小的一个，剩下的仍是最大的 `k` 个。由此可知，遍历结束时堆顶就是答案。

## Java 实现

```java
import java.util.PriorityQueue;

class Solution {
    public int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int num : nums) {
            minHeap.offer(num);
            if (minHeap.size() > k) {
                minHeap.poll();
            }
        }

        return minHeap.peek();
    }
}
```

## PriorityQueue 是什么？为什么不用 LinkedList？

`PriorityQueue` 是优先队列，按元素的优先级决定谁先出队。`PriorityQueue<Integer>` 默认使用整数的自然顺序，最小值优先，内部以最小堆实现。

| 方法 | 作用 | 当前有 m 个元素时的时间复杂度 |
| --- | --- | --- |
| `offer(num)` | 插入元素并维护堆 | `O(log(m + 1))`（摊还） |
| `peek()` | 查看堆顶最小值，不删除 | `O(1)` |
| `poll()` | 取出并删除堆顶，重新维护堆 | `O(log(m + 1))` |

堆只保证父节点不大于子节点，不保证所有元素都按升序排列；直接遍历 `PriorityQueue` 也不保证得到有序结果。

`LinkedList` 是链表。作为普通队列使用时，`offer` 在队尾加入元素，`peek` 和 `poll` 操作队头，不会自动查找最小值。例如依次加入 `3、1、2`：

| 操作 | `PriorityQueue<Integer>` | `LinkedList<Integer>` 普通队列用法 |
| --- | --- | --- |
| `peek()` | 返回最小值 1 | 返回最早加入的值 3 |
| `poll()` | 删除并返回 1 | 删除并返回 3 |

本题超过 k 个候选时，需要淘汰的是最小值。如果直接把代码中的 `PriorityQueue` 换成 `LinkedList`，删除的会是最早加入的元素，不能正确维护最大的 k 个数。

链表也能用于实现这个算法，但需要每次扫描寻找最小值，或者在插入时维护有序链表。两种方式每轮都可能花费 `O(k)`，总时间达到 `O(nk)`；最小堆则将维护成本降低到每轮 `O(log(k + 1))`。

## 堆的变化

以 `nums = [3,2,1,5,6,4]`、`k = 2` 为例：

| 当前元素 | 加入后的候选元素 | 超过 k 时弹出 | 本轮结束保留的元素 | 堆顶 |
| --- | --- | --- | --- | --- |
| 3 | `[3]` | 无 | `[3]` | 3 |
| 2 | `[2,3]` | 无 | `[2,3]` | 2 |
| 1 | `[1,2,3]` | 1 | `[2,3]` | 2 |
| 5 | `[2,3,5]` | 2 | `[3,5]` | 3 |
| 6 | `[3,5,6]` | 3 | `[5,6]` | 5 |
| 4 | `[4,5,6]` | 4 | `[5,6]` | 5 |

最终保留最大的两个数 5 和 6，堆顶 5 就是第 2 大元素。

表格为了方便阅读，将候选元素按升序展示；实际堆并不是完全有序的数组，只保证父节点不大于子节点，堆顶是最小值。

## 关键细节

- **为什么求第 k 大却用最小堆？** 堆保存最大的 k 个元素，需要快速淘汰其中最小的候选，并在最后取出这 k 个元素中最小的值。最大堆的堆顶是最大值，不能直接完成这个操作。
- **为什么先加入，再判断大小？** 新元素也可能是最小的候选，统一加入后再淘汰堆顶，就不必单独比较。堆会短暂达到 `k + 1` 个元素，每轮结束最多保留 k 个。
- **为什么用 `size() > k`，而不是 `>= k`？** 恰好 k 个元素时应该全部保留，否则最终只剩 k - 1 个。
- **为什么用 `if` 就够了？** 每轮最多加入一个元素，而上一轮最多保留 k 个，因此最多弹出一次。
- **重复元素怎么办？** 最小堆允许重复值，不进行去重。两个相同的数仍分别占据一个名次。
- **是否修改输入？** 不修改原数组，候选元素存放在额外的堆中。
- **边界如何处理？** `k = 1` 时只保留最大值；`k = n` 时保留全部元素，堆顶是最小值。单元素、负数和全相等数组也适用。题目保证 `1 <= k <= n`，因此最终堆非空。

## 复杂度

- 时间复杂度：`O(n log(k + 1))`。每个元素插入一次，最多弹出一次，堆大小最多为 `k + 1`。通常在 `k >= 2` 时简写为 `O(n log k)`；`k = 1` 时为 `O(n)`。
- 额外空间复杂度：`O(k)`，用于存储堆中的候选元素。

中文题面要求 `O(n)` 时间复杂度，最小堆方案在一般情况下不满足这一要求。这里按最小堆思路实现，适合练习优先队列及 Top K 问题；若需要期望线性时间，可以使用随机快速选择。
