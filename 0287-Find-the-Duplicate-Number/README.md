# 287. 寻找重复数

给定长度为 `n + 1` 的整数数组 `nums`，每个元素都在 `[1, n]` 内。只有一个数重复出现，但它可能出现两次以上，返回这个重复数。

要求不修改数组，只使用 `O(1)` 的额外空间，并实现 `O(n)` 时间的解法。

[力扣题目](https://leetcode.cn/problems/find-the-duplicate-number/) · [Java 源码](Java/Solution.java)

## 示例

| nums | 返回值 |
| --- | --- |
| `[1,3,4,2,2]` | 2 |
| `[3,1,3,4,2]` | 3 |
| `[3,3,3,3,3]` | 3 |
| `[1,1]` | 1 |

下面按题目保证的合法输入编写，不处理空数组、越界数值或多个不同重复数。

## 思路：把数组看成链表

这道题与 [142. 环形链表 II](../0142-Linked-List-Cycle-II/README.md) 的联系是：**把下标当作节点，把数组值当作下一个节点的下标。**

```text
链表移动一步：p = p.next
数组移动一步：p = nums[p]
```

以 `nums = [1,3,4,2,2]` 为例：

| 当前节点（下标 i） | 下一个节点（nums[i]） |
| --- | --- |
| 0 | 1 |
| 1 | 3 |
| 2 | 4 |
| 3 | 2 |
| 4 | 2 |

从下标 0 出发，路径为：

```text
0 → 1 → 3 → 2 → 4
            ↑   │
            └───┘
```

这里的箭头表示 `i → nums[i]`，图中的数字都是下标。下标 3 和下标 4 都指向节点 2，因为 `nums[3] = nums[4] = 2`。因此，环入口的下标 2，同时就是数组中的重复值。

可以把每个下标理解成一张路牌，数组值就是路牌上写的“下一站去哪”。例如站在 4 号路牌，看到 `nums[4] = 2`，就去 2 号；到了 2 号，看到 `nums[2] = 4`，又回到 4 号。于是路线一直是 `2 → 4 → 2 → 4 → …`。这不是按下标顺序走到 5，而是按数组值跳转。

### 为什么数组访问不会越界？

数组长度为 `n + 1`，合法下标是 `[0, n]`；所有元素值都在 `[1, n]` 内。因此指针初始为 0 时合法，每次读出的数组值也都是合法下标。

快指针的两次数组访问同样安全，可以把表达式拆开理解：

```java
int next = nums[fast]; // next 在 [1, n] 内
fast = nums[next];     // next 是合法下标，更新后的 fast 仍在 [1, n] 内
```

这是两次沿指向跳转，不是把下标加 2。结论依赖题目的输入约束；若数组含负数或大于 n 的值，这份实现不保证访问安全。

### 为什么一定有环？

每个值都在 `[1, n]` 内，所以 `nums[p]` 始终是合法下标，路径不会终止。节点数量有限，不断前进必然再次访问某个节点，从而进入环。

### 为什么从 0 出发找到的环入口就是重复数？

没有数组元素等于 0，所以没有任何节点指向节点 0；节点 0 一定在环外。

从 0 出发进入环时，入口有两个不同的前驱：一个是进入环之前的节点，另一个是环内指向入口的节点。两个不同下标对应的数组值都等于入口下标，说明这个下标对应的数字重复出现。

题目保证只有一个重复数，所以找到这个入口就找到了答案。不需要实际创建链表，也不需要找出数组中的所有环。

## Java 实现

```java
class Solution {
    public int findDuplicate(int[] nums) {
        int slow = 0;
        int fast = 0;

        // 先移动再比较，排除起点处的初始相等。
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        // 从起点与相遇点同速前进，首次相遇的位置就是环入口。
        slow = 0;
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }

        return slow;
    }
}
```

## 第一阶段：找到环内的相遇点

两个指针都从下标 0 出发：

- `slow = nums[slow]`：慢指针走一步。
- `fast = nums[nums[fast]]`：快指针连续走两步。

两者进入环后，快指针每轮相对慢指针多走一步，最终一定相遇。第一次相遇的位置不一定是环入口。

仍以 `[1,3,4,2,2]` 为例，下表只显示每轮完整执行后的结果：

| 移动轮数 | slow | fast |
| --- | --- | --- |
| 0 | 0 | 0 |
| 1 | 1 | 3 |
| 2 | 3 | 4 |
| 3 | 2 | 4 |
| 4 | 4 | 4 |

第一次在节点 4 相遇，但答案是 2，所以不能直接返回第一次相遇的位置。

**为什么使用 `do...while`？** 初始时 `slow == fast == 0`。如果直接写 `while (slow != fast)`，循环一次也不会执行。必须先移动，再判断是否相遇。

### 第一轮为什么是 slow = 1、fast = 3？

第一轮开始时，两者都为 0：

```java
slow = nums[slow];        // nums[0] = 1
fast = nums[nums[fast]];  // nums[nums[0]] = nums[1] = 3
```

快指针的路线是 `0 → 1 → 3`，但 Java 会先算完右侧表达式，再把结果 3 赋给 fast。**fast 不会先被赋值为 1，也不会在中途与 slow 比较。** 两条赋值语句执行完毕后，才判断 `slow != fast`；此时 `1 != 3`，继续第二轮。

### 为什么后面 fast 看起来一直在 4？

当 fast 来到 4 后，每轮走两步，路线都是 `4 → 2 → 4`，所以每轮结束时仍然是 4。它确实走了两步，只是恰好绕完长度为 2 的环。

第二阶段每轮只走一步，fast 的位置才会在 2、4 之间交替。两个阶段的移动速度不同，不能混在一起看。

### slow = 0 什么时候执行？

`slow = 0` 写在整个 `do...while` 循环之后，不是每轮结束后执行。这个例子中，前 3 轮两者不相等，都会继续循环；第 4 轮结束时 `slow == fast == 4`，退出循环后，才执行 `slow = 0`，fast 保持为 4。

## 第二阶段：找到环入口

让 `slow` 回到起点 0，`fast` 留在相遇点。此后两个指针每轮都走一步：

| 移动轮数 | slow（从 0 出发） | fast（从相遇点 4 出发） |
| --- | --- | --- |
| 0 | 0 | 4 |
| 1 | 1 | 2 |
| 2 | 3 | 4 |
| 3 | 2 | 2 |

两者在节点 2 相遇，返回 2。

### 先用这个例子理解：为什么刚好在 2 相遇？

重置后，两者走的路线分别是：

```text
slow：0 → 1 → 3 → 2    走 3 步到入口
fast：4 → 2 → 4 → 2    走 3 步也到入口
```

slow 从 0 到入口需要 3 步。fast 从相遇点 4 到入口，本来只需 1 步，但多走长度为 2 的一整圈后，仍然回到入口：`1 + 2 = 3` 步，恰好与 slow 对上。

前两步 slow 还在环外的 1、3，而 fast 始终在环内的 2、4，所以不可能提前相遇。第 3 步 slow 第一次进入环，两者才在入口 2 碰面。

这不是随便选一个环内节点都能做到的。第一阶段的一倍、两倍速度，保证相遇点回到入口的距离，与起点到入口的距离，相差整数个完整圈。下面说明这个关系为什么成立。

### 一般情况下为什么也成立？

设起点到入口的距离为 `a`，入口到第一次相遇点的距离为 `b`，环长为 `L`，其中 `0 <= b < L`。

第一次相遇时，假设慢指针走了 `s` 步，它可能在环内走过若干完整圈，因此：

```text
s = a + b + mL
```

快指针走了 `2s` 步。两者在环内同一个节点相遇，路程差一定是环长的整数倍：

```text
2s - s = kL
s = kL
a + b = (k - m)L
```

也就是说，`a + b` 是环长的整数倍。从相遇点再走 `a` 步，相当于从入口走 `b + a` 步，恰好回到入口。

与此同时，从起点 0 出发的指针走 `a` 步，也恰好到达入口。在这之前，它还在环外，而另一个指针始终在环内，不可能提前相遇，所以第二阶段第一次相遇就是入口。

例子中 `a = 3`、`b = 1`、`L = 2`，满足 `a + b = 2L`。注意，`a` 不一定等于相遇点回到入口的最短距离，它可以多出若干个完整圈。

## 容易写错的地方

- **不是下标加一。** `slow++` 表示顺序遍历数组；本题沿着 `i → nums[i]` 移动，必须写 `slow = nums[slow]`。
- **快指针不是数值乘二。** 走两步是 `nums[nums[fast]]`，不是 `nums[fast] * 2`。
- **第二阶段两者都走一步。** 此时 `fast` 只是变量名，不再保持两倍速度。
- **起点必须配套。** 本实现第一阶段从 0 出发，第二阶段也回到 0；不能随意改成 `nums[0]`。
- **返回入口下标。** `return slow` 得到重复数；`return nums[slow]` 得到入口的下一个节点，在示例中会错误返回 4。
- **不要求重复数只出现两次。** 出现三次或更多次仍然适用，全相等数组也能正确找到入口。
- **不修改原数组。** 两阶段只读取数组并更新两个局部变量。

## 复杂度

- 时间复杂度：`O(n)`。第一阶段进入环后至多再经过一圈就相遇，第二阶段走起点到入口的距离。
- 额外空间复杂度：`O(1)`。只使用两个指针变量，没有创建链表、集合或额外数组。
